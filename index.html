Things I've Built: Multi-System AI Agents & Custom MCP Tools

MODEL CONTEXT PROTOCOL (MCP) MULTI-SYSTEM AGENT WORKFLOWS

Multi-System AI Agents for Better Workflow

Coordinated Agent Swarms • Sandboxed Local Execution

ACTIVE ARCHITECTURE

To solve context degradation and make AI truly effective for real software engineering, I built multi-system AI agent workflows. Rather than forcing a single model to hold an entire codebase and perform every task sequentially, specialized agents coordinate in parallel to inspect, plan, write, execute, triage, and review tasks with seamless tool access.

01. Orchestrator & Planner

Breaks high-level user intent into structured dependency graphs (DAGs) and delegates sub-tasks to specialized domain agents.

02. Code & Refactor Agent

Inspects local directories, writes unit implementations, and refactors components through sandboxed file MCP tools.

03. Shell & Diagnostics Agent

Executes verified build scripts, test suites, and git operations locally with explicit human confirmation gates.

04. Error Triage & Log Agent

Continuously monitors debug output, extracts stack traces, and suggests targeted code diffs without copy-pasting.

05. Research & Scraping Agent

Pulls fresh API documentation, dependency changelogs, and benchmarks live into context via headless browser scraping.

06. UI Inspector & Visual Agent

Captures dev server screenshots, validates responsive CSS rendering, and flags UI anomalies using vision models.

Sandboxed execution boundaries with human-in-the-loop verification Unified Multi-Agent Protocol

Problem-Solving Approach

PRACTICALITY OVER COMPLEXITY

One thing that defines how I approach technology is that I prefer practical problem solving. When I encounter a technical problem, I look at the chain of causation rather than jumping to superficial workarounds:

STEP 01

What is happening?

Observe symptoms & error output

STEP 02

Why is it happening?

Trace logs, configs, root cause

STEP 03

What options do I have?

Evaluate architectural solutions

STEP 04

Most practical fix?

Implement sustainable solution

I'm not particularly interested in adding technology simply because it sounds impressive. If a feature doesn't meaningfully improve a project, I'd rather leave it out. This mindset has become especially important while developing complex software systems, where unnecessary complexity can make a system harder to maintain.

Debugging Style: When something doesn't work, I prefer investigating the actual cause—whether checking dependencies, logs, configurations, APIs, or system limitations—rather than simply looking for a temporary workaround.
